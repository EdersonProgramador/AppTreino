## P0 — BLOQUEIA PRODUÇÃO (corrigir primeiro)

### Segurança (API)

1. AUTENTICACAO POR EMAIL SEM TOKEN NO /auth/google — apps/api/src/modules/auth.routes.ts:480-603
   - O endpoint aceita `email` puro sem token Google (idToken ausente -> verifyGoogleIdToken retorna null, nao e erro).
   - Qualquer pessoa que souber um email loga na conta (ou cria conta) sem provar identidade.
   - FIX: exigir idToken valido/verificado SEMPRE quando provider GOOGLE; validar aud/iss; usar email SOMENTE do token verificado.

2. JWT SEM EXPIRACAO — apps/api/src/modules/auth.routes.ts:289,372,414,472,518,597 e apps/api/src/modules/checkout.routes.ts:409; registro em apps/api/src/server.ts:59-61
   - Tokens assinados sem `expiresIn` -> validos para sempre, sem revogacao.
   - FIX: configurar `sign: { expiresIn: ... }` no @fastify/jwt (ex.: 7d ou 24h) e tratar 401 expirado no frontend.

3. BACKDOOR DE DEV ATIVO EM PRODUCAO — apps/api/src/modules/auth.routes.ts:116-118,195-229,273-320
   - `admin@app-treino.local` / senha `123456` cria usuario ADMIN.
   - `roleForDemoEmail` (116-118): qualquer email contendo "admin" vira ADMIN.
   - Fallback de senha `123456` (212, 306).
   - FIX: bloquear TODOS os fallbacks de dev quando `NODE_ENV === "production"` (fail closed); exigir senha forte; remover auto-criacao de usuarios @app-treino.local em producao.

4. UPLOADS: MIME CLIENT-CONTROLLED + ARQUIVOS PUBLICOS — apps/api/src/modules/admin.routes.ts:18-37,646-653 e apps/api/src/server.ts:70-73
   - Confia no mimetype declarado pelo cliente; extensao vem do filename original.
   - Possivel enviar evil.html como "image/png" e ele e servido publicamente por /uploads (stored XSS).
   - FIX: validar extensao/conteudo real (magic bytes), forcar `Content-Disposition: attachment` e/ou `X-Content-Type-Options: nosniff`, autenticar /uploads se necessario.

### Dados / Migracao

5. SCHEMA DIVERGENTE DA MIGRACAO — apps/api/prisma/schema.prisma vs apps/api/prisma/migrations/*
   - `TicketMessage`, `WorkoutFavorite` e enum `WAITING_STUDENT` no schema SEM migration correspondente.
   - `prisma migrate deploy` falha em producao -> chat de atendimento quebra (500).
   - FIX: gerar migration (ex.: `npx prisma migrate dev --name add_ticket_messages_workout_favorites_enum`), revisar SQL, commitar migration.

6. ASAAS_API_URL DEFAULT SANDBOX — apps/api/src/env.ts:19 e .github/workflows/deploy-hostgator.yml:105-118
   - Default e https://api-sandbox.asaas.com/v3 e o workflow de deploy NAO seta a URL de producao.
   - Pagamentos reais iriam para a sandbox silenciosamente.
   - FIX: exigir `ASAAS_API_URL` em producao; adicionar `PRODUCTION_ASAAS_API_URL=https://api.asaas.com/v3` aos secrets/var do GitHub.

### Deploy / Infra

7. DOCKERFILE API QUEBRADO E ORFAO — Dockerfile.api:27
   - 13 deps de workspace aninhadas sob apps/api/node_modules NAO sao copiadas -> imagem nao sobe.
   - Nenhum workflow builda/push a imagem (infra orfa).
   - FIX: copiar `apps/api/node_modules` ou rodar `npm ci --omit=dev` no stage runner; adicionar job de build/push ou remover o Dockerfile.

8. DEPLOY HOSTGATOR DESTRUTIVO SEM ROLLBACK — .github/workflows/deploy-hostgator.yml:125-145
   - Remove dist antes de copiar (125-128), migra DEPOIS do swap (143-144), sem health-check (145).
   - FIX: parar->backup->swap atomico (dir blue/green), migrar antes do swap, POST /health apos deploy, plano de rollback (dir anterior + dump do DB).

### Frontend

9. SEM ERROR BOUNDARY — apps/web/src/main.tsx:6-9 e apps/web/src/App.tsx:743-938
   - Qualquer erro de render/hook zera a tela inteira (foi o bug da pagina do aluno).
   - FIX: criar ErrorBoundary no topo do main.tsx com fallback + botao recarregar.

10. SEM ROUTER — apps/web/src/App.tsx:744,923-936
    - Refresh volta para a home, botao voltar sai do app, sem deep links.
    - FIX: router hash-based (minimo) ou react-router; persistir view/section no hash/localStorage.

11. DEMO LOGIN NO UI DE PRODUCAO — apps/web/src/App.tsx:783-800,1327-1334
    - Botoes "Demo admin/aluno" com credenciais hardcoded (admin@app-treino.local / 123456).
    - FIX: remover ou gate por `import.meta.env.DEV`.

12. SEM LOGOUT EM 401 — apps/web/src/api.ts:30-101 e apps/web/src/App.tsx:746,756-774
    - So `/me` limpa o token; qualquer outra chamada com token expirado deixa o usuario preso.
    - FIX: interceptor central em api.ts que limpa token + redireciona para login em qualquer 401.
